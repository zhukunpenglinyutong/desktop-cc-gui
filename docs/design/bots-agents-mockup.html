智能体 → Bot：智能体区改版 · 交互设计稿

把「名称 + 图标 + 提示词」的静态预设，升级成有身份、有能力、有记忆、能指定运行后端、能被查看和导出的长期助手。本稿覆盖设置页 智能体与提示词 → 智能体 的列表、编辑器（身份 / 人格 / 工作规则 / 能力 / 运行 / 记忆 / 定时 / 协作）、拼装预览，以及输入框 # 选择器和会话里的身份体现。

00

这一版改了什么

旧版智能体是「一个弹窗里填三个字段」；新版把它当成一个长期存在的 Bot，字段分区块、每块都能看能改能导出，并且随时能看清楚这些配置最终拼成什么提示词。

① 身份优先

先让人（和其他 Bot）认出「这是谁」：头像、名称、头衔、一句话简介、唯一 @标识。身份常驻左栏，切到任何分区都不会丢。

② 说的和做的分开

「怎么说」（人格 SOUL）与「怎么做」（工作规则 AGENTS）拆成两页，各自有引导和用量上限，不再堆在一个提示词框里。

③ 配置 → 提示词可见

「拼装预览」抽屉按顺序列出每个区块的字符数与开头内容，空区块自动省略、超限实时提示。

从 BoardUI agent-creator 借了什么

  • 头像工作室：直接用 BoardUI agent-creator 的组件——情绪轮盘套在实时头像外圈、九种轮廓沿底部弧形排布、颜色行是光泽色球 + 自定义取色器（AgentAvatar / EmotionPicker / ShapeArc / GlossSwatch）。
  • 卡片行：一行 = 图标 + 标签 + 说明 + 右侧控件，说明文字常驻，不靠 tooltip 才看得懂。
  • 窄列身份 + 宽列内容：左栏只放「它是谁」，内容区只放「它会什么」。
  • 没照搬的：语言 / 通知 / 语音与播放速度那三段偏好属于具体场景，没有对应产品需求，不引入（agent-preferences 未采用）。
01

智能体列表

列表行的信息量按「认人 → 认能力 → 认状态」分三层：名称 + 头衔在第一行，简介在第二行，运行后端和规模（技能 / 记忆 / 定时）收在右侧。置顶与 ⋯ 只在悬停时出现，不抢视线。

要点

  • 「新建」右侧是导入 ▾：从文件导入 .zip / 从内置目录复制 / 粘贴 Markdown。
  • 筛选条按用户会问的问题分组：全部 / 置顶 / 自定义 / 内置，而不是按数据字段。
  • ⋯ 菜单：编辑、复制、导出为 zip、隐藏、删除。删除 danger 色且进 ConfirmDialog。
  • 被隐藏的 Bot 折成一条「已隐藏 · n」，不消失——隐藏只是不在 # 菜单出现。
  • 空列表时不给一张大插画，给 3 个可点的起步模板（讲解 / 评审 / 写作）+「从内置目录复制」。
02

Bot 编辑器 · 身份与头像

左栏是「它是谁」，常驻不切换：大头像工作室 + 名称 / 头衔 / 简介 / @标识。右栏按分区切换。编辑器是弹窗（Esc / 点背景 / 右上角 X 都能关），不是全屏页。

要点

  • 生成形象 = BoardUI 的纸片头像引擎（canvas）：9 种轮廓、16 种表情、HSL 颜色 + 自定义取色器，离线可用，不需要用户找图。
  • 不再提供「表情符号 / 图片」两种来源：已存在的 emoji 头像照常显示，编辑器给一行说明，用户挑形状/表情/颜色时才替换。
  • 舞台右上角一个骰子：一键随机形状 + 表情 + 预设色。
  • 简介不是装饰：它会进其他 Bot 的「协作者」区块，是 Bot 之间互相认识的唯一信息，所以给字数上限和一行说明。
  • @标识由名称自动生成（中文转拼音）、保证唯一，用于群聊 @ 和委派；改了名称不会静默改标识，需要用户确认。
  • 保存是自动的：离开分区、切换 Bot、关闭编辑器都落盘，头部显示「已自动保存 14:32」；失败时原地变红并给重试。
  • 内置目录里的 Bot 打开是只读态，第一次编辑时提示「将复制一份到我的智能体」，不静默改内置数据。
03

Bot 编辑器 · 人格与工作规则

原来一个「提示词」框拆成两个：人格决定语气、性格、立场；工作规则决定职责、流程、限制、输出格式。两页结构一样，避免用户学两套东西。

要点

  • 旧提示词迁移到人格（默认决策），工作规则留空 —— 空区块在拼装时整块省略，行为与旧智能体一致。
  • 底部用量条是人格 + 工作规则合计 / 10,000，超过 80% 变橙、超过上限变红并提示拆分到 Skills。
  • 「插入模板 ▾」：空白、结构化骨架（职责 / 流程 / 输出格式 / 不做什么）、从内置 Bot 整段复制。
  • 两页都做重复检测：同一句话两边都有时给一条黄色提示，因为模型会读到两次，占额度还互相打架。
  • Markdown 是可选的：不认语法的用户写纯文本也没问题，编辑器不强行套格式。
04

Bot 编辑器 · 能力（Skills / 工具 / MCP）

阶段 1 只做 Skills

Skills 是这次升级里最实在的一块：从「一段提示词」升级成可导入、可分配的技能包（SKILL.md + 脚本 + 参考资料），Bot 平时只看到名称和描述，需要时才读全文。

要点

  • 未勾选的 skill 对这个 Bot 完全不可见——不列在 prompt、也不能被 skill_view 读到（阶段 1 验收项）。
  • 「全部技能 *」是一个明确的开关，等价于 skills: ['*']；将来新建的 skill 自动生效。默认关闭，避免 Bot 悄悄长出能力。
  • 索引只占 prompt 的「名称 + 描述」，底部实时显示 索引 420 / 3,000 字；超出按使用频率截断并注明还有几个。
  • 行内显示使用次数，帮用户判断哪些 skill 其实没在用。
  • 工具与 MCP 带阶段徽标：不可用时不隐藏，置灰并说明「阶段 3 可用」，避免用户以为功能坏了。
  • 没有装任何 skill 时，空状态直接给「从技能库导入」和「新建 SKILL.md」两个入口，不写「暂无数据」。
05

Bot 编辑器 · 运行后端

阶段 3

同一个 Bot，可以选直连模型、Claude Code 或 Codex 来干活。检测结果显示在卡片上，没装的置灰并说清楚原因，不让用户点了才发现跑不了。

要点

  • 三张卡平铺，选中态用边框 + 底色，未安装的卡 disabled + 原因，不隐藏（用户需要知道有这条路）。
  • CLI 模式必须选工作目录，没选时「保存」禁用并给原因——默认决策里写的是「禁止运行，提示用户选择目录」。
  • 权限模式是逐档升级的三档：每次询问（默认）/ 自动安全 / 完全放行；完全放行要二次确认，且卡片上标红。
  • CLI 模式下的记忆走「会话结束必触发一次复盘」，这一条要在界面上明说，否则用户会以为没有记忆。
  • 「重新检测」是刷新型动作（转圈 → 对号），结果带时间戳，不每次打开都重跑。
06

Bot 编辑器 · 记忆 / 定时 / 协作

阶段 2 / 3 / 4

三个分区共用同一套页面骨架，都用「开关行 + 列表 + 一个主操作」，不各造一套。切换页签即可在本稿里对比。

记忆

  • 三个开关：启用记忆 / 写入需要审批 / 后台复盘，另加「每 N 轮复盘」。
  • 两条用量条分开：Bot 笔记 2,200（每个 Bot 各自一份）、用户画像 1,375（全局共享，所以标「全局」并用不同措辞，避免用户以为删了会影响别的 Bot）。
  • 最近条目带来源徽标（你要求 / Bot 自己 / 复盘）和时间，可点进来源会话——记忆不是黑盒。
  • 导出 MEMORY.md、清空（二次确认）放这里；聊天里的 💾 记忆已更新 开关也放这里。
07

拼装预览：配置是怎么变成提示词的

右上「拼装预览」打开右侧抽屉，按顺序列出每个区块、字符数和开头一行。空区块显示为「已省略」，超限区块变橙。这是这一版最重要的「可解释性」入口。

要点

  • 顺序固定：应用基础 → 身份 → 人格 → 工作规则 → 用户画像 → Bot 笔记 → Skills 索引 → 记忆说明 → 协作者；空区块整块省略。
  • 抽屉里每个区块的开头一行是活的（跟着左边编辑即时变），不是渲染时的快照。
  • 会话中途改配置不会改变当前会话的提示词（会话开始时冻结快照）；想立刻生效要点「刷新上下文」，按钮旁写明「会让缓存失效」。
  • 「复制全文」用于调试和给别人看；不含任何密钥（凭证不在这条链路上）。

一句话：Last-Modified 是「东西什么时候改的」，ETag 是「东西现在长什么样」。
时间能对上但内容被改回来了，Last-Modified 会误判成没变；ETag 用内容指纹，就不会。
所以浏览器两个都带的时候，优先信 ETag。

1. 生成形象要不要做？
做：Bot 有辨识度、离线生成、无需素材；代价是头像数据要从「emoji 字符串」扩成结构体（{type,shape,color,face}），迁移多一步。不做：只保留 emoji + 图片，工作量少一半。
2. 编辑器放在哪？
A. 设置页内的全屏编辑器（本稿方案，改动小、跟着设置页走）；B. 独立中心页签（像插件中心，不占设置页、可从侧栏直达，但要接入中心面互斥体系）。
3. 阶段 2–5 的页签现在显示吗？
A. 显示但置灰 + 「阶段 N 可用」说明（本稿方案，用户能预期路线）；B. 只显示已实现的页签，做完一阶段加一个（界面更干净，但每次升级布局会变）。

验收对齐

  • 旧智能体全部迁移成功、内容一致，# 选择器正常。
  • 只有人格的 Bot 与旧智能体行为完全一致（拼装结果除新增空区块外内容相同）。
  • 导入标准 SKILL.md 目录后，Bot 能在需要时调用 skill_view 并按 skill 执行；未启用的 skill 不可见。
  • 导出的 Bot 在另一台机器上能完整导入。
