# 2026-11 · v1.2.0 被企业终端安全软件告警复盘

> 结论：**不是投毒**。告警的每一项都能对应到我们自己的源码。问题在于实现方式命中了 EDR（终端检测与响应）的启发式规则。
> 本文记录事实、根因、修复与遗留项。防复发的规则写在根目录 `AGENTS.md` 的「安全敏感行为」一节，本文是它的依据。

## 1. 事件

- 2026-11-01，有用户反馈：所在公司的信息安全团队把 CC GUI 1.2.0（Windows）判定为恶意软件，告警项是「系统进程注入、缓存本地凭据、控制键盘和截屏」。
- 用户自己定位到：程序在找 CodeBuddy 的登录凭据，执行了 `cmdkey /list`，入口在 `CodeBuddyAuthSection.tsx`。
- CodeBuddy 是腾讯的产品。在腾讯系安全体系的企业里，这等于「第三方程序在翻腾讯账号的凭据」，必然升级处理。

## 2. 告警与代码的对应关系

| 告警项 | 对应实现（1.2.0） | 实际触发条件 |
|---|---|---|
| 缓存本地凭据 / 凭据窃取 | `engine/codebuddy.rs`：Windows 下以 `CREATE_NO_WINDOW` 隐藏窗口执行 `cmdkey /list`，在全部凭据目标名里搜 `codebuddy`。macOS 用 `security find-generic-password -s` 依次试 3 个服务名，Linux 用 `secret-tool search` | 打开「设置 → CLI 管理 → CodeBuddy」就执行，之后每次窗口获得焦点再执行一次（30 秒缓存）。**引擎已禁用、甚至没安装 CodeBuddy 也会触发** |
| 缓存本地凭据（读取真实令牌） | `usage_limits/credentials.rs`：macOS 用 `security find-generic-password … -w` 读出 Claude Code 的 OAuth 令牌，并读取 `~/.claude/.credentials.json`、`~/.codex/auth.json`，再请求官方用量接口 | 用量插件取得 `limits.read` 权限后自动轮询，事先没有告知用户 |
| 控制键盘和截屏 | 主程序 exe 直接链接 `xcap`（截屏）、`enigo`（SendInput 注入键盘鼠标）和全局热键 | 只有 `/ccgui-cua` 才真正执行。但主 exe 的导入表本身就带有这些能力，静态扫描会直接报 |
| 系统进程注入（无告警详情，以下为高概率候选） | `enigo` 的 SendInput（多数 EDR 归为「输入注入」）；`plugin_host.rs` 遍历所有窗口并对每个所属进程调用 `OpenProcess`，以查找微信；`open_app.rs` 隐藏启动 PowerShell，`Add-Type System.Drawing … ToBase64String`；主 exe 会被 CLI 以 `--computer-use-mcp` 参数再拉起一份 | 分别由插件调用、加载程序图标、电脑操控回合触发 |
| 放大因素 | Windows 安装包没有 Authenticode 签名（macOS 版已签名并公证） | 无签名的程序加上以上行为，信誉评分更低 |

## 4. 根因

1. **只验证功能对不对，没问这个行为在安全软件眼里像什么。** 为了「准确显示登录状态」去枚举系统凭据库，在功能上是合理的；但在 EDR 看来，这就是凭据侦察。审查跟进（含 AI 修复）没有这一层检查。
2. **隐藏窗口加上敏感工具，就等于隐蔽行为。** `CREATE_NO_WINDOW` 本来是为了不闪控制台窗口，但和 `cmdkey`、PowerShell 组合后，正好符合恶意软件「隐藏执行侦察命令」的特征。
3. **禁用只是视觉遮罩，副作用照常执行。** `CliConfigBody` 的禁用态只是盖了一层 `absolute` 遮罩，组件照样挂载、照样探测。再加上「挂载即探测」和「焦点变化时重新探测」，一个被禁用的功能也在反复执行敏感操作。
4. **高危能力和常驻主进程放在同一个 exe 里。** 截屏、输入注入只在电脑操控时才需要，却链接进了一直运行的主程序。
5. **用隐藏脚本做原生 API 就能做的事。** 提取图标用了 PowerShell 加 System.Drawing 再转 Base64，形态和「截屏后编码外传」的脚本一样。
6. **读取其他程序的凭据前没有告知用户。** 用量插件在后台读取 Claude 和 Codex 的令牌，用户并不知情。
7. **Windows 发布没有代码签名。**

## 5. 本次修复

| 项 | 改动 | 回归保护 |
|---|---|---|
| CodeBuddy 凭据探测 | 删掉三个平台的探测和对应 IPC。账号区改为中性说明加「终端登录」按钮，登录状态由 CLI 自己管理 | `CodeBuddyAuthSection.test.tsx`（挂载和焦点变化都不触发任何 IPC）；`engine::codebuddy` 的 `never_spawns_credential_store_tools` |
| 图标提取 | 改用 `SHGetFileInfoW` + `GetIconInfo` + `GetDIBits` 在进程内完成（`open_app/program_icon.rs`），不再启动隐藏的 PowerShell | `open_app::program_icon` 单元测试；用官方 rustc 做过 Windows 目标类型检查 |
| 读取 CLI 令牌 | 后端 `usage_limits::consent::require` 在读取任何凭据前拒绝（错误前缀 `CredentialConsentRequired: `）。前端 `withCredentialConsent` 弹出确认框，逐项列出本机实际路径（或钥匙串服务名）和唯一发送目标；拒绝后本次运行不再询问。插件详情页可以允许或撤销。Web 访问端没有同意路由 | `usage_limits::consent` 测试；`credential-consent.test.ts`；`CredentialConsentControl.test.tsx` |
| 截屏 / 输入注入 | 拆成独立的 `ccgui-computer-use` 程序（`src-tauri/src/bin/ccgui-computer-use/`），只在电脑操控回合由 CLI 拉起；主程序不再链接 xcap、enigo；保留 `--computer-use-mcp` 作为转发兼容层 | `computer_use` 的 `main_app_sources_never_reference_driver_crates`；macOS 上 `nm -u` 确认主程序没有 `CGEventPost`、`CGWindowListCreateImage` 等导入 |
| 代码签名 | `release.yml` 配置签名证书后，用 `scripts/windows-sign.ps1` 给 exe、辅助程序、安装器和卸载器做 Authenticode 签名（支持 Azure Trusted Signing 或证书），构建后校验签名，任何文件签名无效即失败；没配置证书时构建仍成功，但会给出未签名警告 | `Verify Authenticode signatures` 步骤 |

## 6. 遗留项（未处理，需要单独评估）

- **签名证书尚未就绪**：在配置证书之前，Windows 包仍然没有签名。所需的 secrets 和 vars 见 `scripts/windows-sign.ps1` 文件头。
- **插件 IPC 守卫实际从未生效（更正本节早先的说法）**：Tauri 2.11 起 `__TAURI_INTERNALS__.invoke` 不可改写，`hardening.ts` 的包装在正式版上一次也没装上。任何插件代码都能直接调用全部宿主命令，包括 `cli_credential_consent_set(true)`、返回明文 API Key 的 `get_cli_config`，以及原样返回 `~/.codex/auth.json` 的 `official_config_read`。此前写的「只能借异步回调绕过、令牌不会交给插件」不成立。同意弹窗只约束宿主自己的读取路径，不是插件隔离边界。处理方案见 `2026-11-security-audit.zh-CN.md`。
- **辅助程序仍在安装包里**：拆分降低的是常驻进程的行为暴露面。静态扫描整个安装目录时仍会看到 `ccgui-computer-use.exe`。
- `plugin_host.rs` 的微信窗口采样（`EnumWindows` 加上对每个窗口进程 `OpenProcess`），由插件触发。
- 其他隐藏窗口的子进程：`engine/grok.rs` 用 PowerShell 建目录联接，`engine/registry.rs` 和 `engine/job.rs` 调用 `taskkill` / `cmd`。都有正当理由，但属于同类特征。
- 桌宠在 Windows 上定时轮询 `GetCursorPos`；电脑操控期间注册全局热键 Esc。
- 百度统计上报、局域网 Web 访问和 Cloudflare 中继：后两项都需要用户主动开启，但都属于远程控制类能力，企业安全团队可能会问到。

## 7. 对外答复要点

1. 告警项均来自 CC GUI 自己的功能代码，不是供应链投毒。要彻底排除，可以把安全团队分析的样本 SHA256 和 GitHub Release 上的安装包对比。
2. 下一个版本移除凭据库探测和隐藏 PowerShell，并把截屏和键鼠控制拆到独立程序，只在用户主动使用电脑操控时运行。读取 CLI 令牌前会先列出读取位置并征得同意。
3. 如果需要定位「进程注入」具体是哪一项，请对方提供告警名称、进程树和命令行。
4. 官方 v1.2.0 Windows 安装包 `CC.GUI_1.2.0_x64-setup.exe` 的 SHA256 为 `dc9848f465c2172301f5542c98d8fd27f1efe6dd48f3942be072ab3ab9b5ab60`。它由 GitHub Actions 从 main@6c46345 构建，2026-10-31 15:54（UTC）由 `github-actions[bot]` 上传，之后未被替换。可以请对方用样本哈希对照：一致则说明是官方构建，不一致则样本来自其他渠道。

## 8. 发版前自查

在仓库根目录执行。命中以下内容并不代表一定有问题，但每一处都要能说明「为什么需要」「由谁、什么时候触发」「是否隐藏窗口」：

```bash
# 凭据库 / 他人凭据
grep -rnE 'cmdkey|CredEnumerateW|CredReadW|find-generic-password|secret-tool|vaultcmd|\.credentials\.json|auth\.json' src-tauri/src
# 隐藏窗口的子进程与脚本
grep -rnE 'CREATE_NO_WINDOW|0x0800_0000|powershell|pwsh|EncodedCommand|-ExecutionPolicy' src-tauri/src
# 截屏 / 输入注入 / 跨进程（驱动只在 src/bin/ 下；主程序侧现有的已知命中只有：
# computer_use.rs 的守卫测试本身、plugin_host.rs 的微信窗口采样、history/edit.rs 对自身进程的 OpenProcessToken）
grep -rnE 'xcap|enigo|SendInput|keybd_event|SetWindowsHookEx|OpenProcess|ReadProcessMemory|EnumWindows' src-tauri/src --exclude-dir=bin
# 全量进程枚举、端口强杀、下载即执行（2026-11 全仓自查新增，见 2026-11-security-audit.zh-CN.md）
grep -rnE 'ProcessesToUpdate::All|netstat|lsof|taskkill|irm .*\| *iex|curl .*\| *(ba)?sh|ExecutionPolicy' src-tauri/src
# 挂载即执行、远程脚本、预览沙箱
grep -rnE 'useAutoProbe|addEventListener\("focus"' src | grep -v test
grep -nE 'script-src[^;]*https:|allow-same-origin' src-tauri/tauri.conf.json src/features/files/HtmlPreview.tsx
```
